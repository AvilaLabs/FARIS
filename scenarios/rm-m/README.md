# RM-M design file

`rm-m.faris-design.json` is the `faris-design/v0.1` design file for the reference model RM-M of the CAD transport
risk tests (S0). `rm-m.operating-history.json` is the operating history it links: the demo's operating assumptions
with `service_limits` emptied, because a CAD design takes its limits from its replacement groups.

The STEP file is not committed. `rm-m.step` is regenerated by
`integrations/openmc/risk_tests/build_rm_m.py` (CAD environment). The file the design was written for has sha256

```
79b1481b5867baaa33b6c5c7d79e0f6c8fcd81f6683b424aab87bf00d2277a17
```

(the value in the S0 model card). OpenCASCADE writes a timestamp into the STEP header, so a rebuilt file may hash
differently; if it does, copy the new hash into `cad.step_sha256`. Check 3 then confirms that the geometry is the
same.

To check it, put the built file next to the design file as `rm-m.step` and run

```bash
faris design check rm-m.faris-design.json --report check.json \
  --cad-python PATH_TO_CAD_PYTHON \
  --openmc-python PATH_TO_OPENMC_PYTHON --cross-sections PATH_TO_cross_sections.xml
```

The draft was written by `faris design init rm-m.step`. The materials, roles, replacement group and plasma block
were then filled in from `rm_m_spec.py`, `rm_m_openmc.py` and `rm_m_model_card.json`, with the same materials and
dimensions S0 used, each labelled `published` or `authored` as the model card labels it.
