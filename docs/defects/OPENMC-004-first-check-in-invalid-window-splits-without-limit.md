# OPENMC-004: a particle whose first weight-window check falls in an invalid bin is scaled as if born in a window of 1.0, and splits up to `max_history_splits`

Status: drafted, not reported. Verification and significance: see [README.md](README.md). Found by S0e's E2′ stall and
diagnosed on 2026-10-11 (`docs/notes/CAD_TRANSPORT_S0F.md`, facts). Draft for an issue against `openmc-dev/openmc`.

## Versions

| | Result |
| --- | --- |
| OpenMC 0.15.3 (conda-forge, `openmc0153dd`) | reproducer: 200 histories finish in 1.2 s with every bin valid, and do not finish in 120 s with the source bin invalid |
| OpenMC 0.16.0 (conda-forge, `openmc016`) | the same |
| `develop` at aa4afc41e (2026-10-10) | the same code (`src/weight_windows.cpp` lines 966–967 and 982–988) |

## What happens

At a particle's first weight-window check, `apply_weight_windows` records the centre of the window it is in as
`wgt_ww_born`, and every later window for that particle is scaled by `wgt_born / wgt_ww_born`. If that first check falls
in a bin whose bounds are −1 (no window), `wgt_ww_born` is set to 1.0 instead (0.15.3 `src/weight_windows.cpp` lines
80–86; 0.16.0 lines 966–967).

Windows written by `WeightWindowGenerator` are normalized so that the largest lower bound is 0.5, and FW-CADIS windows
sit orders of magnitude below that over most of a deep-penetration model. The same generator writes −1 for any bin whose
flux estimate it rejects (zero, or relative error above the threshold), including bins inside the source. A particle that
first meets a window in such a bin then carries a weight of 1 against unscaled windows of order 1e-7. It is split by
`max_split` at every event until `settings::max_history_splits` (10,000,000) is reached. Nothing is reported; the batch
never ends.

On RM-M (FARIS's 30-solid tokamak, DAGMC), FW-CADIS windows generated by random ray on a 117,504-bin cylindrical mesh
had 2 invalid bins in the 0.82–20 MeV group, one of them in the plasma core. 3.45e-4 of the source sites fall in an
invalid bin. A production of 10,000 histories per batch never finished its first batch in 600 s. With the 16 invalid
bins filled from their neighbours (geometric mean), 30,000 histories finished in 8.8 s.

## Reproducer

`XS=/path/to/cross_sections.xml python repro.py {valid|invalid} OUTDIR` (needs Fe56). A 100 cm iron cube, a 14.1 MeV
point source, a 10 × 10 × 10 mesh of windows falling from 0.5 (as a generator normalizes them), `max_split` 1000,
checkpoints at collisions and surfaces. The two cases differ only in the source bin's bounds.

```python
import sys, os, time, subprocess
import numpy as np
import openmc

case, out = sys.argv[1], sys.argv[2]
os.makedirs(out, exist_ok=True); os.chdir(out)
fe = openmc.Material(); fe.add_nuclide("Fe56", 1.0); fe.set_density("g/cm3", 7.8)
mats = openmc.Materials([fe]); mats.cross_sections = os.environ["XS"]
box = openmc.model.RectangularParallelepiped(-50, 50, -50, 50, -50, 50, boundary_type="vacuum")
geom = openmc.Geometry([openmc.Cell(fill=fe, region=-box)])
mesh = openmc.RegularMesh(); mesh.lower_left = (-50, -50, -50); mesh.upper_right = (50, 50, 50); mesh.dimension = (10, 10, 10)
lower = (0.5 * 10.0 ** (-np.indices(mesh.dimension).sum(axis=0) / 4.0))[..., np.newaxis]
if case == "invalid":
    lower[5, 5, 5, 0] = -1.0  # the source bin, as the generator writes a bin it rejected
upper = np.where(lower > 0, 5.0 * lower, -1.0)
ww = openmc.WeightWindows(mesh, lower, upper, energy_bounds=[0.0, 2.0e7], particle_type="neutron", max_split=1000)
s = openmc.Settings(); s.run_mode = "fixed source"; s.batches = 1; s.particles = 200; s.seed = 1
s.source = openmc.IndependentSource(space=openmc.stats.Point((2.5, 2.5, 2.5)), energy=openmc.stats.Discrete([14.1e6], [1.0]))
s.weight_windows = [ww]; s.weight_windows_on = True; s.weight_window_checkpoints = {"collision": True, "surface": True}
openmc.Model(geom, mats, s).export_to_model_xml()
t0 = time.monotonic()
try:
    subprocess.run(["openmc", "-s", "1"], check=True, capture_output=True, timeout=120)
    print(f"{openmc.__version__} {case}: 200 histories in {time.monotonic() - t0:.1f} s")
except subprocess.TimeoutExpired:
    print(f"{openmc.__version__} {case}: did not finish 200 histories in 120 s")
```

Output (1 thread, Linux x86-64):

```text
0.15.3 valid: 200 histories in 1.2 s
0.15.3 invalid: did not finish 200 histories in 120 s
0.16.0 valid: 200 histories in 1.2 s
0.16.0 invalid: did not finish 200 histories in 120 s
```

## Possible fixes

- Leave `wgt_ww_born` unset while the particle is outside a valid window, and set it at the first valid one (the
  scaling then means what its comment says: relative to the window the particle started in).
- Or have the generator never write −1 inside its energy range: fill a rejected bin from its neighbours, or warn.
- A default `max_history_splits` far below 1e7, or a warning when a history reaches it, would turn a silent stall into
  a visible one.

## Workaround used by FARIS

Fill every invalid bin inside the windowed energy groups from its valid face neighbours (geometric mean, repeated until
none is left) before production (`integrations/openmc/risk_tests/s0f_common.py`, `fill_invalid`). The result stays
unbiased: weight windows change only the variance and the cost.
