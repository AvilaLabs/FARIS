# Release package for 0.1.1: split download and native launcher

Recorded 2026-10-06. 0.1.1 keeps the 0.1.0 study, results and `.faris` format. It changes how the study is
distributed so that the download is smaller, opens without Python, and can be built for Windows and macOS.

## Why

The 0.1.0 package is one 112.5 MB archive. Most of it is evidence that the app never reads at launch: the eight
Avila Core case and workspace archives (51 MB compressed) and the outage-duration probe histories (24 MB). The
package opens through `launch.sh`, which runs a Python script, so it needs `python3` and works on Linux only.

## Two archives, one package

A release ships two archives that unpack into the same folder, `FARIS-<version>/`:

| Archive | Contents | Platform |
| --- | --- | --- |
| `FARIS-<version>-<os>-<arch>.tar.gz` (`.zip` on Windows, later) | the **app part**: programs, the four transport bundles, the sweep bundles, the control scenario, the operating assumptions, `README.md`, licences, `SOURCE_PROVENANCE.md`, the package index | one per platform |
| `FARIS-<version>-evidence.tar.gz` | the **evidence part**: every other indexed file (Core archives and manifests, saved-study descriptors, inspections, Core exports, comparisons, event histories, sensitivities, studies, outage-duration probes, support files, `inputs/`, `verify.sh` and the verifier scripts) | the same bytes for every platform |

The app part alone opens the whole study. The evidence part adds the Core receipts in the Evidence step and is
what `verify.sh` checks. Unpacking the evidence archive over the app folder completes the package.

Decision: the outage-duration probe histories ship in the evidence part, not regenerated by the verifier.
Regenerating them would need byte-identical histories from every platform's build, and cross-platform floating-point
reproducibility of the history engine has not been established.

Decision: Avila Core stays in the app part. The app uses it for **Compile study**. Reopening the saved studies does
not run Core: `faris_engine::case_archive::inspect_saved_case` checks the recorded receipts in Rust, so the evidence
part does not depend on which platform's Core is installed. The recorded receipts name the Linux Core that produced
them, as recorded fact.

## Package index v0.5

`package-index.json` stays a single index in the app part, so one hash (`package-index.sha256`) still binds
everything. Changes from v0.4:

- `schema_version`: `faris-recorded-demo-package/v0.5`.
- Every `files[]` entry gains `"part": "app"` or `"part": "evidence"`.
- New `parts`: `{"app": {"file_count", "bytes"}, "evidence": {"file_count", "bytes", "archive_name"}}`, where
  `archive_name` is the evidence archive's file name, for the next-step message.
- `local_runtime.platform` becomes `{"os": ..., "arch": ...}` using Rust's `std::env::consts::OS` and `ARCH`
  values (`linux`, `macos`, `windows`; `x86_64`, `aarch64`). The Python verifier maps `sys.platform` and
  `platform.machine()` onto these.
- `local_runtime.executables` paths carry `.exe` on Windows.
- `local_runtime.launcher` becomes `{"kind": "native", "executable": "faris-app"}`. `launch.sh` and
  `scripts/launch_recorded_demo.py` are removed. `local_runtime.verifier` still names `verify.sh`, now in the
  evidence part.

Assignment rule: the app part is exactly the files the app reads at launch, plus `README.md`, `licenses/**`,
`SOURCE_PROVENANCE.md` and `bin/**`. Everything else indexed is evidence. The packager asserts that every path the
app opens is in the app part.

## Native launcher: package mode in `faris-app`

`faris-app` opens a package directly. There is no separate launcher program.

**Finding the package.**
- `--package DIR` names it explicitly.
- With no study file and no data flags, the app looks for `package-index.json` beside its own `bin/` folder
  (`current_exe()/../..`), and on macOS also in `../Resources/package` for a later `.app` bundle. Found: package
  mode. Not found: the embedded geometry demo, as now.
- Double-clicking `bin/faris-app` therefore opens the study on every platform.

**Checks before anything is loaded** (fail closed; mirrors the launch-relevant part of `verify_index`):
- `package-index.sha256` is exactly `sha256:<hex>  package-index.json\n` for the index bytes; index at most 16 MiB.
- Schema v0.5 and the v0.4 status string, unchanged.
- `local_runtime.platform` equals this build's `{os, arch}`.
- The running executable's SHA-256 equals `faris_app_sha256`. When `--package` was given explicitly and the hash
  differs, the app continues and labels itself a development app binary not covered by the package index (stderr and
  the Evidence step). When the package was found automatically, a mismatch fails.
- Every app-part file: a safe relative path (normal components only, no symlink), a regular file, and the indexed
  size and SHA-256.
- Evidence part: present if every evidence file exists, absent if none does, incomplete otherwise. The launcher hashes
  only the evidence files it reads (archives and manifests, during extraction). Full verification stays with
  `verify.sh`.

A failed check opens the window with nothing from the package loaded and a failed badge that says why and what to
do next (download again and check `SHA256SUMS`). Nothing is printed only to a console, because Windows and macOS
users will not see one.

**Loading.** The same inputs the 0.1.0 launcher passed: the two port bundles, the control scenario and its two
bundles, `operating-assumptions.json`, the indexed sweep bundles (each hash-checked against `sweep.runs[]`), and
`bin/avila-core` as the Core executable.

**Runs directory.** Default outside the package: `$XDG_STATE_HOME/faris/recorded-demo-runs/<package folder name>`
(`~/.local/state` fallback) on Linux, `~/Library/Application Support/FARIS/recorded-demo-runs/<name>` on macOS,
`%LOCALAPPDATA%\FARIS\recorded-demo-runs\<name>` on Windows. `--runs-directory` overrides; it must resolve outside
the package.

**Evidence.**
- Present: a background thread extracts the eight trees into a private temporary folder
  (`tempfile::TempDir`, prefix `faris-recorded-demo-`), writes the four saved-study descriptors and the
  `faris-recorded-materialization/v0.1` marker exactly as the 0.1.0 launcher did, and hands them to the existing
  `queue_descriptors` path. The folder lives until the app exits; exit cancels and joins the thread.
- Absent: the Evidence step says "Core receipts not included", why (this download does not include the evidence
  part) and the next step (download `<archive_name>` from the same release, unpack it into the package folder, reopen
  FARIS). Everything else works.
- Incomplete: the same, saying how many evidence files are missing.

Decision: no free-space pre-check. The standard library has no portable free-space call and no crate for it is in
the lockfile. Extraction fails with the operating system's error, which the marker carries to the Evidence step
together with the expanded size needed (from the index).

**Extraction.** A new `faris_study::tar::extract_recorded_tree(archive, manifest, destination, cancel)` with the
semantics of `scripts/recorded_archives.py` `extract_archive`:
- manifest schema `faris-recorded-tree-archive/v0.1` and its bounds; archive SHA-256 and size match the manifest
  and the index;
- exactly one gzip member and no trailing bytes;
- USTAR regular files and zero-size directory entries only, canonical names, no repeats, file/directory prefix
  conflicts refused;
- every file's size and SHA-256 equal the manifest record, the set of files equals the manifest, and the totals
  equal the declared totals and stay within the per-tree caps;
- after the last member, at least two zero blocks, a multiple of 512 bytes, all zero, at most
  `TRAILER_LIMIT = 4096 * 1024 + 12288` bytes;
- files created exclusively and read-only, inside a fresh destination that is removed on any failure; cancellation
  checked between blocks.

One pass (verify while extracting, remove on failure) replaces Python's preflight plus extraction pass, because the
destination is a fresh private folder that is deleted on failure.

## Release archives

`make_release.py` writes both archives, `RELEASE_NOTES.md` and one `SHA256SUMS` covering both. The archives are
deterministic: sorted members, owner and group 0, mtime fixed to the release commit time, gzip header mtime 0.

## Verifier

`verify_recorded_demo.py` accepts v0.5 only (a 0.1.0 package carries its own verifier). It needs both parts and
refuses a missing evidence part with the archive name to download. It runs on Linux, where the recorded Core
executes.

## Other platforms: retargeting the Linux package

The recorded study data are produced on Linux, and the Windows and macOS programs cannot run there. The desktop
workflow (`.github/workflows/desktop.yml`) uploads per platform `bin/` and `build.json`
(`faris-desktop-build/v0.1`). `scripts/retarget_package.py --package LINUX_PKG --build BUILD_DIR --output OUT_DIR`
turns a finished, verified Linux v0.5 package into that platform's package: it refuses unless the build's FARIS and
Core commits and `faris --version` equal what the Linux package recorded and every program has its recorded hash and
size; it hard-links every file except `bin/*`, the index and `README.md`, installs the build's programs, and rewrites
the index (`local_runtime.platform` and `executables`, the three pins, the `bin/*` file records, the app-part totals).
Two records are added to the index: `evidence_recorded_with` (the Linux platform and the `faris` and Core hashes that
produced the recorded evidence; every v0.5 index carries it, equal to its own pins on Linux) and `desktop_build` (the
build record).

`make_release.py` reads the platform from the index. For Windows and macOS it executes nothing: the version comes
from `desktop_build.faris_version` and the programs' hashes and sizes are checked. Windows writes a deterministic
`.zip`, macOS a `.tar.gz`. A release is the Linux run (both archives), then `make_release.py --app-only` once per other
platform, which writes only the app archive and appends its line to `SHA256SUMS`. The evidence archive is
byte-identical whichever package it is built from.
