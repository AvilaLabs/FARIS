# Quality assurance

How FARIS proves itself before it ships and keeps proving itself afterwards: requirement traceability, automated testing at every level, independent cross-validation, graded quality assurance mapped to ASME NQA-1 software elements, configuration control, release gates, defect handling and test data. Physics accuracy targets are in [06-accuracy-and-validation](06-accuracy-and-validation.md); performance gates are in [08-performance](08-performance.md); evidence receipts are in [16-evidence-and-provenance](16-evidence-and-provenance.md). Reference hardware and models are in the [index](README.md#reference-hardware-and-models).

The NQA-1 mapping is a mapping only. FARIS never claims compliance, qualification or licensing use; a self-declared compliance claim is itself a defect (QA-052). Coverage and mutation percentages are gates for trends and gaps, not evidence of correctness; the validation matrix (VAL-050) is the evidence.

## Traps

- **Coverage is gameable.** 100 % line coverage with weak assertions proves little. Pair it with mutation score and with the V&V matrix, and say which kind of coverage a number is (QA-030, QA-031).
- **Mutation scores on numerical kernels mislead.** Equivalent mutants inflate the denominator and tolerance-insensitive tests deflate the score. Use it as a trend with triaged survivors, not as a pass mark alone (QA-031).
- **Test count is not assurance.** GMAT's 13,000 scripts are a precedent for traceability and nightly discipline, not a number to match. A thousand tests for one requirement help nothing for the next (QA-012, QA-095).
- **Code-to-code agreement is not validation.** Cross-checks live in QA for verification only; validation lives in VAL (QA-041).
- **NQA-1 mapped is not NQA-1 compliant.** No one can self-declare compliance, and no regulator qualifies a fusion code today. Claim only the mapping (QA-052).
- **A flaky test is a lost signal.** Retrying until green hides real bugs, particularly in Monte Carlo tests with loose tolerances (QA-086).
- **Reproducible builds on other platforms.** Signing embeds timestamps; claim Linux only until proven (QA-063).
- **Green CI on shared runners.** Wall time varies by 10–30 %; performance gates use instruction counts or dedicated hardware (PERF-051).
- **Passing the gate by editing the matrix.** The trace matrix, the "Now" column and verdicts are generated; a hand-edited cell is a defect (QA-002, QA-009).
