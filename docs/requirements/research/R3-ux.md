## 1. Best-in-class landscape

### 1.1 Usability metrics and benchmarks
- SUS (Brooke 1996). Scale 0-100, 10 items. Sauro & Lewis curved grading (MeasuringU, https://measuringu.com/sus/):
  mean across studies ~68 = 50th percentile; 74 = B- (per MeasuringU page); 80.3 = A / top 10%. "Excellent" adjective rating ~ 85 (Bangor, Kortum, Miller 2009, J. Usability Studies 4(3),
  https://uxpajournal.org/determining-what-individual-sus-scores-mean-adding-an-adjective-rating-scale/ ; Excellent mean ~85.5, Best imaginable ~90.9).
- Reference SUS values for real products [U numbers, see section 0]: Kortum & Bangor 2013, Int J Hum-Comput Interact 29(2), doi:10.1080/10447318.2012.681221 -
  Google search ~93, Gmail ~83, Amazon ~82, Excel ~57 (approximate, unverified). Business/enterprise software averages cluster 65-72 (MeasuringU, unverified).
  No public SUS exists for Onshape, Fusion 360, COMSOL, Ansys Discovery, ParaView, Blender, Figma that I could cite;
  I found no primary source. Treat vendor SUS claims as absent. Public usability evidence for these tools is
  anecdotal/academic (e.g. ParaView/VTK usability is studied mainly via workshop papers).
- UMUX-Lite: 2 items, 7-point (Lewis, Utesch, Maher 2013, CHI, doi:10.1145/2470654.2481287). Regression to SUS-equivalent:
  SUS_pred = 0.65*((item1+item2-2)*100/12)+22.9 (as published; verify). Useful for in-app micro-surveys.
- SEQ (Single Ease Question), 7-point post-task; average ~5.5 (Sauro, https://measuringu.com/single-question/). Target >= 5.5 per task, flag tasks < 4.8.
- Task success: average completion ~78% across 1,100 tasks (MeasuringU, https://measuringu.com/task-completion/; unverified exact). Time on task is lognormal; report geometric mean/median, not mean.
- Sample sizes: NN/g 5 users per round finds ~85% of problems at p=0.31 (https://www.nngroup.com/articles/why-you-only-need-to-test-with-5-users/);
  NN/g quantitative usability testing recommends 40 for narrow CIs, 20 typical (https://www.nngroup.com/articles/quantitative-user-research-methods/ ; unverified exact). SUS stabilises at ~12-14 participants (Tullis & Stetson 2004,
  https://www.researchgate.net/publication/228609327). 5 users does NOT give benchmarkable SUS; the CI half-width at n=20 is roughly +/-6 SUS points (SD ~ 17; Sauro).
- Frameworks: ISO 9241-11:2018 (effectiveness, efficiency, satisfaction in context), ISO 9241-210 (human-centred design), ISO/IEC 25062 (Common Industry Format
  for usability test reports), ISO 9241-110 (dialogue principles), Nielsen 10 heuristics (https://www.nngroup.com/articles/ten-usability-heuristics/), Google HEART (Rodden 2010, https://research.google/pubs/measuring-the-user-experience-on-a-large-scale-user-centered-metrics-for-web-applications/), NASA-TLX for workload.
- Time-to-first-result: no standardised benchmark exists for engineering software. Developer-tools analogue: "time to first hello world" (TTFHW) and 5-minute quickstart conventions. Blender/ParaView/COMSOL publish tutorials, not time-to-value stats. Treat target values as provisional.

### 1.2 Responsiveness
- Nielsen: 0.1 s feels instantaneous, 1 s keeps flow, 10 s is the attention limit (Miller 1968; Card, Robertson, Mackinlay 1991; https://www.nngroup.com/articles/response-times-3-important-limits/).
- Doherty & Thadani 1982 (IBM Systems Journal 21(4)): productivity rises sharply when response < 400 ms.
- Seow 2008 "Designing and Engineering Time": instantaneous 0.1-0.2 s, immediate 0.5-1 s, continuous 2-5 s, captive 7-10 s.
- Frame budgets: 60 Hz = 16.67 ms, 120 Hz = 8.33 ms, 144 Hz = 6.94 ms. Google RAIL: respond <100 ms, frames <16 ms, idle work chunks <50 ms (https://web.dev/articles/rail). INP good <= 200 ms, poor > 500 ms (https://web.dev/articles/inp).
- Direct-manipulation latency: users detect ~ 1-10 ms in dragging (Ng, Lepinski, Wigdor, Sanders, Dietz, UIST 2012; Jota et al. CHI 2013, doi:10.1145/2470654.2470658) - target is drag-follow latency <= 1-2 frames.
- Leading tools (unverified, vendor claims): Ansys Discovery runs GPU "Live" physics giving near-instant structural/thermal/CFD updates on simplified models (https://www.ansys.com/products/3d-design/ansys-discovery); Figma's WebGPU renderer blog gives no fps number [V: https://www.figma.com/blog/figma-rendering-powered-by-webgpu/]; Blender viewport runs at display refresh for scenes up to millions of triangles on discrete GPUs (no single cited number). ParaView ships parallel server-side rendering for billions of cells.

### 1.3 Interaction patterns found in best-in-class tools
Unlimited/long undo (Fusion timeline and parametric history; Onshape feature tree + version history; Blender configurable undo steps (default and max [U])), command palette (VS Code Ctrl+Shift+P, Blender F3 search, Figma Ctrl+/ quick actions, ParaView Ctrl+Space quick launch), customisable keymaps (Blender, Fusion), autosave (Blender configurable autosave timer, recover last session; Onshape continuous cloud save with no manual save), version history/branch/merge (Onshape - https://cad.onshape.com/help/Content/versionmanager.htm), saved workspaces (Blender workspaces, ParaView layouts), dark/light themes, HiDPI, multi-window (Blender, ParaView), tooltips with shortcuts and manual links (Blender Python tooltips, F1 manual), templates/startup files, example galleries, inline validation (COMSOL error/warning nodes in model tree), expert vs guided modes (COMSOL model wizard + full tree; Fusion workspaces).

### 1.4 Accessibility
- WCAG 2.2 (W3C Rec Oct 2023, https://www.w3.org/TR/WCAG22/) AA criteria relevant to a desktop app: 1.4.1 Use of Color; 1.4.3 Contrast Minimum 4.5:1 (3:1 large text); 1.4.4 Resize Text 200%; 1.4.11 Non-text Contrast 3:1; 1.4.13 Content on hover/focus (tooltips dismissable, hoverable, persistent); 2.1.1 Keyboard; 2.1.2 No Keyboard Trap; 2.4.3 Focus Order; 2.4.7 Focus Visible; 2.4.11 Focus Not Obscured (Minimum); 2.5.7 Dragging Movements (single-pointer alternative); 2.5.8 Target Size Minimum 24x24 CSS px; 3.3.1/3.3.3 error identification/suggestion; 3.3.7 Redundant Entry; 4.1.2 Name, Role, Value; 2.2.2 Pause/Stop/Hide for moving content; 2.3.1 three flashes. Reduced motion: 2.3.3 (AAA) and OS prefers-reduced-motion setting.
- Regulatory: Section 508 (ICT Refresh, 2017) incorporates WCAG 2.0 A/AA (https://www.section508.gov/); EN 301 549 v3.2.1 (2021) clause 11 covers software and maps to WCAG 2.1 AA (https://www.etsi.org/deliver/etsi_en/301500_301599/301549/03.02.01_60/en_301549v030201p.pdf); European Accessibility Act applies from 28 June 2025 to products/services in scope (Directive 2019/882). Vendor documentation convention: VPAT 2.5 / Accessibility Conformance Report (https://www.itic.org/policy/accessibility/vpat).
- AccessKit/egui: eframe has an `accesskit` integration (egui >= 0.20 era) exposing the widget tree via UI Automation (Windows), NSAccessibility (macOS), AT-SPI (Linux). Standard egui widgets (label, button, text edit, checkbox, slider) expose role/label; custom painted content (plots, wgpu 3D viewport) exposes nothing unless FARIS adds nodes manually. Maturity versus NVDA/Orca/VoiceOver: limited; text-edit and complex widgets partial (unverified - check egui CHANGELOG and AccessKit README at https://github.com/AccessKit/accesskit before committing). Known egui gaps (unverified): no RTL/bidi or complex-script shaping in the stock text stack; IME support variable by platform.
- CVD: ~8% of men and ~0.5% of women have red-green deficiency (https://www.nei.nih.gov/learn-about-eye-health/eye-conditions-and-diseases/color-blindness/types-color-blindness). Viridis/magma (Smith & van der Walt, SciPy 2015, https://bids.github.io/colormap/), cividis (Nunez, Anderton, Renslow 2018, PLOS ONE, doi:10.1371/journal.pone.0199239), Crameri "Scientific colour maps" (Nature Communications 2020, doi:10.1038/s41467-020-19160-7; https://www.fabiocrameri.ch/colourmaps/). Jet/rainbow is non-monotone in lightness, creates false boundaries, fails in greyscale/CVD (Borland & Taylor 2007, IEEE CG&A, doi:10.1109/MCG.2007.323435).

### 1.5 Scientific visualization
- Uncertainty: error bars are widely misread (Belia et al. 2005, Psych Methods 10(4), doi:10.1037/1082-989X.10.4.389); Correll & Gleicher 2014 "Error bars considered harmful" (IEEE TVCG, doi:10.1109/TVCG.2014.2346298) recommends violin/gradient plots; hypothetical outcome plots improve probability estimation (Hullman, Resnick, Adar 2015, PLOS ONE, doi:10.1371/journal.pone.0142444); fan charts (Bank of England); Padilla, Kay, Hullman 2022 survey "Uncertainty Visualization".
- Feature bar: ParaView (https://docs.paraview.org/) - slices, clip, contour/isosurface, volume rendering, glyphs, stream tracer, threshold, calculators, plot-over-line, spreadsheet view, linked cameras/views, animation, Python tracing, client-server with MPI, state files, catalyst in situ. VisIt and Tecplot 360 equivalent plus probe, scatter, time-series. Large-data performance claim: ParaView/VTK-m handle 10^8-10^9 cells in parallel; single-GPU interactive limit ~10^7 triangles (rule of thumb, unverified).
- Honest colour bars: show units, explicit min/max, log vs linear stated, clamp indicator, and never different ranges across compared panels (Tufte small multiples; Munzner "Visualization Analysis & Design" 2014).

### 1.6 Errors, trust, documentation, collaboration
- NN/g error messages: be explicit, human-readable, polite, precise, constructive (https://www.nngroup.com/articles/error-message-guidelines/). Heuristics #1, #5, #9.
- Diataxis (https://diataxis.fr/): tutorials, how-to guides, reference, explanation as four separate forms. Rust ecosystem: `#![deny(missing_docs)]`, docs.rs, doctests as executed examples.
- Collaboration references: Figma multiplayer + comments (https://www.figma.com/blog/how-figmas-multiplayer-technology-works/ - CRDT-like), Onshape branch/merge with real-time co-edit and permissions (https://cad.onshape.com/help/Content/branching-merging.htm), Google Docs-style suggestion mode.

## 3. Traps

- SUS is a global satisfaction measure, not a diagnostic. A high SUS with n = 5 is noise (CI roughly +/-10 or more). Never quote SUS from a convenience sample of the team; benchmark with domain users who did not build it. SUS also rewards familiarity: experts of ParaView rate ParaView highly. Percentile claims depend on the Sauro/Lewis database, which skews toward web/consumer products; the 68 mean is not an engineering-software mean.
- "5 users find 85% of problems" applies to formative problem discovery for similar users in a homogeneous population, not to benchmarking or to multiple user types. Run 5 per distinct role.
- Mean latency hides stalls; users feel P99 frame spikes. Gate on P95/P99 and on max frame during jobs. Measure at the glass (present), not at event dispatch. egui immediate-mode repaint on every frame wastes CPU; test idle.
- "1 s recalculation" claims depend on the parameter box; sweeps with changed geometry trigger transport reruns that cost minutes. Distinguish sliders that reuse cached transport (fast) from ones that cannot, and say so in UI.
- Progress bars that lie (non-linear ETA) are worse than indeterminate spinners. Progressive Monte Carlo results show shrinking uncertainty; do not present a partial TBR as final.
- Accessibility via automated checkers covers perhaps a third of WCAG issues; a green axe-like scan is not conformance. WCAG was written for web; apply it to desktop by analogy (CSS px -> logical px) and say so in the ACR. Canvas/wgpu content is invisible to AccessKit unless explicitly mirrored: egui accessibility will look good on buttons and fail on the product's main value, the 3D and plot views.
- Colour: a "viridis" default is not enough if comparisons use different ranges, diverging maps hide a zero point not centred, or categorical colours exceed ~7 distinguishable hues. Rainbow in third-party imported images (OpenMC plots) leaks in. Colour bars with clipped ranges can fake a flat result.
- Error bars: +/-1 sigma intervals are read as bounds (Belia 2005). MC standard error excludes cross-section, geometry, and model uncertainty; showing only statistical error implies false precision. Label the uncertainty source and show "statistical only" when so.
- 2-sigma flags in compare views across many cells/parameters give multiple-comparison false positives (about 5% at 2 sigma); say how many comparisons were made.
- Undo that does not undo derived/cached results or file-side effects (exports, external-run directories) gives silent inconsistency. Undo of a long run should cancel, not rewind.
- Autosave overwriting the good file with a corrupt one; always journal, never overwrite in place.
- Locale: decimal-comma locales corrupting CSV/CLI/file parsing is a classic failure; unit conversions (cm vs m, MeV vs J) are the bigger risk than language.
- Docs: a docs-coverage percent counts pages, not truth; tutorials rot silently unless executed in CI. Diataxis is a framework, not a quota; "coverage by quadrant" counts can be gamed by thin pages.
- Onboarding completion metrics rise by making the tour shorter, not better; measure retained comprehension (quiz) and first-own-study success.
- Collaboration features (real-time multi-user) are expensive and conflict with hash-bound, append-only evidence receipts; branch/merge and review-bundle sharing satisfy most needs without a server.
- Vendor claims (Ansys "real time") come from marketing; real-time Discovery uses simplified physics and is not a fidelity reference for transport.
- Unverified: egui/AccessKit current feature state, exact MeasuringU task-success figure, SUS regression constants, ParaView scale rules of thumb, NN/g quantitative sample sizes. Verify before baselining.
