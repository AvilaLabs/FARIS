# Evidence and provenance

How FARIS proves where a number came from and whether it can still be trusted: receipts, hashes, kind labels, reproducibility, export stamps, packed and referenced evidence, defect notices and the long-term readability of old studies. Receipts are produced through Avila Core; FARIS never edits a verdict. Targets are on the **reference laptop (RL)** where timing matters; see the [index](README.md#reference-hardware-and-models) for RL, RW and the reference models RM-S, RM-M and RM-L. Reproducibility has four determinism classes, assigned per result and recorded in its receipt (PRV-020): bit-identical, cross-platform tolerance, seed-bitwise and statistically consistent.

## Reproducibility

| ID | Requirement | Target | Verification | Basis | Phase | Now |

## Traps

- A receipt that exists is not a result that is correct. Input hashes establish identity, not scientific correctness (AGENTS.md); do not report "100 % with receipts" as a quality measure.
- An RO-Crate export that nobody can replay is compliance theatre. The metric is replay success on a clean machine, not file presence.
- "Reproducible" without a determinism class misleads. Monte Carlo is bitwise only under a fixed seed, decomposition, build and architecture.
- Hashing the compressed file rather than the content makes recompression look like tampering. Hash the content and say which.
- Referenced evidence displays fully, so a green screen can hide missing receipts. The Evidence step, not the number display, decides what is checked.
- Byte-identical reports break silently when a font, library or timestamp changes. Test with a fixed clock and keep the masking rule narrow.
- A kind label that a person can edit is a decoration. The label must follow from the inputs.
- "Old files open" is untested without an archived fixture from every release.
