# Security

How FARIS protects the people who open its files, install it and sign in. FARIS reads files from other people, runs external solvers and links many third-party crates, so the targets cover untrusted input, integrity, fuzzing, the supply chain, the optional Avila Labs sign-in, adapter sandboxing, offline use, export-control marking and vulnerability handling. Research outputs are not a security boundary: a checker's verdict is not a defence against a hostile file. See the [index](README.md#reference-hardware-and-models) for RL, RW and the reference models RM-S, RM-M and RM-L. Nothing here is legal advice; items that touch law or regulation need counsel before the stated gate.

## Sign-in and secrets

The optional Avila Labs sign-in (commit cab0cf3) uses the `avila-account` 0.1.1 crate with features `ui` and `client`: a device-code flow against `https://api.avilalabs.org` (`/api/device/code`, `/api/device/token`, `/api/auth/me`, `/api/auth/logout`). The bearer token is stored in `credentials.json` (mode 0600 on Unix) in `~/.config/avila` or `AVILA_CONFIG_DIR`, written atomically. Debug output redacts the token, redirects are refused, and plain http is accepted only for loopback. A signed-in session asks `/api/auth/me` every 60 seconds; a signed-out session makes no calls. A first-visit prompt appears in interactive runs and not in scripted runs.

## Traps

- A Scorecard of 10 measures repository hygiene, not application security. A clean score can ship a vulnerable app.
- cargo-audit only knows reported advisories, and cargo-vet is only as good as the audits imported. "0 known vulnerabilities" is a statement about a database.
- Counting `unsafe` ignores dependencies and C libraries. The forbid lint covers own crates only.
- A fuzz run of 24 hours with a thin corpus proves little. Measure coverage of the parser, and keep reproducers.
- Content addressing detects change; it does not stop zip bombs, traversal, duplicate entries or symlinks. Those need their own tests.
- A token file with mode 0600 is only as safe as the account. Malware running as the user reads it. Prefer the OS credential store and short-lived tokens.
- "Offline-capable" claims fail on background polling. Measure idle network traffic signed in and signed out.
- Auto-update is a remote-code-execution channel. A signed update that can be rolled back to a vulnerable version is an attack.
- Export-control marks are labels, not legal advice. Never let the tool say a study is or is not controlled.
