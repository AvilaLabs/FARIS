# Geometry and model

How FARIS defines, imports, checks, simplifies, meshes, edits and compares the scene a
study runs on. One scene is the single authority for display, solver inputs, tallies and
component identity. Reference models RM-S, RM-M and RM-L and the reference laptop (RL) are
defined in [the index](README.md#reference-hardware-and-models). Speed targets for opening,
rendering and limits live in [08-performance.md](08-performance.md) and are referred to,
not repeated. Accuracy of transport results on this geometry belongs in
06-accuracy-and-validation.md; this file states what the geometry layer must guarantee
so that those results mean something. A geometry that runs is not a geometry that is right:
every check below is there to stop a clean-looking run on a broken model.

## Traps

- A model that runs is not a model that is right. Zero lost particles in 10⁶ histories does not prove a watertight geometry; leaks hit rarely. Run the integrity checks, not only the transport.
- A TBR from an idealised radial build looks like a design result. Without ports, ribs, supports and manufacturing allowances it overstates the real number, so it must carry the idealised label.
- Volume agreement of a total hides cell-level errors that cancel. Check every cell.
- A display cutaway is a picture, not a solver geometry. Never let a view option change the model that was run.
- Mesh quality metrics can pass while the mesh is too coarse for the physics. Check voxel size against the mean free path as well.
- Homogenising constituents conserves mass but changes streaming and self-shielding. Conservation of mass is not a statement about TBR.
- Symmetry that is claimed but not checked gives plausible wrong answers. Verify the symmetry, then use it.
- A repaired CAD model is a different model. It needs a new hash and a volume diff, not a quiet fix.
